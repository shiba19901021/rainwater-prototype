# Prototype 1A.5 驗收紀錄

本次只增加回合控制與天氣故事排程。固定時間步長、雙緩衝、水量守恆、水文、取水與城市供水步驟，以及設施、地圖、既有天氣與平衡設定，均與修改前 1A 原始碼逐字相同。未加入污染或其他新系統。

## 操作與排程

- 預設 2:00；開始前每次 ±30 秒，可設定 1:00、1:30、2:00、2:30、3:00、3:30、4:00。
- 開始後鎖定本輪總時間與模式；可暫停、繼續、切換 1×～4×、提前結束。時間到即停止且保留水況。重跑或重新選城市後可設定下一輪。
- 新增 `control/round.js` 分段，排程數值集中在 `roundConfig`；每 0.5 模擬秒呼叫原引擎一次。畫面幀率與倍速只决定何時執行這些步驟，不改變任何一步的雨量與順序。
- 30 秒為故事區塊，通常在區塊前 10 秒平滑銜接雨量。正式 UI 顯示整輪故事，沒有增加工程儀表。
- 自動模式為可重現的固定故事，不隨機抽取 W6；偏濕增加雨量壓力，偏乾先少雨累積壓力再降雨恢復。極端／複合才串接久旱與豪雨。
- 原 W1～W6、三波豪雨及其他診斷雨程保留在原引擎與 debug 工具；正式操作由新的講師排程驅動。城市選擇不會偷偷切換講師模式。

| 總時間 | 一般故事 |
|---|---|
| 1:00 | 穩定／趨勢 → 壓力 |
| 1:30 | 穩定 → 趨勢 → 壓力 |
| 2:00 | 穩定 → 趨勢 → 壓力 → 恢復 |
| 2:30～4:00 | 增加穩定與恢復，主要壓力保持一個 30 秒區塊 |
| 4:00 | 穩定 90 秒 → 趨勢 30 秒 → 壓力 30 秒 → 恢復 90 秒 |

60／90 秒短回合依需求省略獨立恢復區塊。短複合情境將降雨轉折壓縮在最後一塊；建議使用 2:00 以上觀察完整的久旱、供水恢復與後續洪水。複合模式允許多重壓力，與一般模式分開。

## 開始播放偶發停止修正

實際 app 的動畫函式混用 `requestAnimationFrame` 畫面起始時間與事件中的 `performance.now()`。初始化、開始／繼續或頁面顯示事件可能在同一畫面較晚發生，使下一次動畫計算出負時間差。`playRoundFrame` 拒絕負值並拋出 `Invalid playback`，動畫未能排入下一次畫面，因此按鈕顯示模擬中卻沒有播放。

修正在 UI 動畫邊界將負時間差視為零，並讓上一個時間標記保持單調遞增；不修改排程、固定步長、供水或水文。新增 `tests/playback-ui.test.mjs`，直接執行正式 app 的開始事件與動畫函式，模擬初始化、開始、繼續與切回頁面後較早的畫面時間戳。四項測試在修正前皆失敗，修正後確認不報錯、下一幀仍排入且模擬確實前進；加入 `audit.mjs`。

修正後 `node audit.mjs` 共 48 項全部通過。瀏覽器實測開始後時間確實前進，暫停維持 0:30.5，切換 3 倍速繼續後前進至 0:53.5，水況同步更新，沒有錯誤或警告。驗證畫面為 `ui-p1a5-playback-fix.jpg`。
