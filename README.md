## Prototype 1C.2：城市功能受災與恢復

保留名目生活點數，新增有效功能。住宅、商業、工業、農地、公共服務會因有害自由地表積淹水或缺水失能；洪水與缺水取較嚴重的一項，不重複扣減。污染沒有直接失能規則，公園的休閒也不因承水或乾旱扣點。需求目標仍為 12／12／4／3。

壓力解除後功能逐步恢復。無公共服務時，輕／中／重度約需 15／36／60 模擬秒；有效公共服務達標可加速至 10／24／40 秒，最高 1.5 倍。公共服務本身受災後加成同步下降，只加快恢復，不改水系統。

玩家主畫面顯示有效值／需求，受損時保留「已建」數字。城市狀態按四項最低滿足比例分為良好（90%）、受壓（70%）、不足（40%）、嚴重失能。格子左上 ◐／⏸／↻ 表示功能受壓／失能／恢復中，原紅色「淹」仍保留；點格可看功能與恢復百分比。

## Prototype 1A.6：正常開局與乾旱累積

每次新城市、開始前配置完成或按「重跑」，由正常水資源起點開始：外部供水 100%、每河段水量 30、非河川土壤濕度 45%、地表無有害積水。有調節池才提供容量 50% 的初始蓄水。這些值集中在 `balanceConfig.waterSupply`；開局水量獨立記入 `totals.initialWater`。

少雨先增加連續的 `droughtStress`。無雨前 25 模擬秒外部供水維持 100%，25.5 秒後開始依壓力漸進下降；有效降雨逐步降低壓力與恢復供水。雨強低於 0.1 視為不足，小雨 0.12 已能減輕壓力。住宅／工業需求、容量、取水上限與原洪水參數未改。

為避免原自動釋水在缺水前排光開局備援，少雨時有限保留開局那份調節池水；城市用水會真實扣除它。有效降雨後解除保留，回到原滯洪釋水，沒有新增水源或容量。重跑代表新的教學回合，重建同一正常起點；回合中暫停／繼續不補水。

偏乾 2 分鐘先晴天，再少雨累積，最後持續乾燥。極端／複合建議至少 2:30；選此模式時會把短於 2:30 的時間調至 2:30，仍可手動改回短回合。W6＋極端／複合 2:30：0～90 秒累積乾旱，90～120 秒降雨恢復，120～150 秒豪雨。較短回合仍能播放，但不保證完整出現缺水後恢復。

`npm run debug:opening` 產生 S1～S5 診斷數據；詳細參數、時間軸、洪水回歸與限制見 `debug/PROTOTYPE-1A6-REPORT.md`。修改前版本在 `debug/prototype-before-drought-buffer.html`。本版停在 1A.6，沒有污染系統。

## Prototype 1A.5：沿用的講師回合控制

## 可調參數

在 HTML 的 `config/facilities.js` 分段調整 facilityConfig；`config/weather.js` 分段調整 weatherConfig 與現有兩種自動排程；`config/balance.js` 分段調整 balanceConfig。地圖位於 `data/map.js`，預設配置位於 `data/scenarios.js`。

本次沒有改設施相對值、入滲、土壤容量、滯洪容量倍率或釋水速度。公園／森林／下凹公園／調節池每格設計容量仍是 4.5／9／18／45。新增的接收能力、壓力起點與壓力曲線也是集中測試值，不是工程尺度。

## 每步規則

固定每步 0.5 模擬秒；速度選項只改執行步數。

1. 各格加入降雨；陸地土壤少量乾燥，依飽和度入滲並填入設施剩餘容量。
2. 使用這一刻的共同快照，計算下一格／河段的壓力與剩餘接收空間。
3. 各來源提出地表傳水與設施釋水需求。同一受水格的全部來源共享接收空間、按需求比例分配；受水端已有積水或河川高水位時，效率下降。
4. 只扣除被接受的水；未排出的地表水留在原格，未釋出的蓄水留在設施。河道依同樣規則逐段向南，出口排出流域。
5. 河川超量沿既有兩岸路徑溢岸，並共享河岸格剩餘接收能力；沒有新增隨機或次要流向。
6. 最後合併傳入量；到達的水可填入現有設施空間，但不能在本步再次入滲、釋水或往下一格流動。
7. 使用自由地表水判定積淹水。設計容量內的蓄水不算災害；容量外自由水超安全門檻仍算設施外溢。河川高水位與本步實際溢岸分開標示。

接收能力限制傳入量，不會刪除本格降雨或把水量裁到上限。水量帳仍為：累積降雨＝自由地表＋河川＋設計蓄水＋土壤水＋累積出口／土壤乾燥損失。

## 三種開發雨程

1. 一般降雨：小雨 10 秒、大雨 20 秒、停雨 120 秒。
2. 強豪雨：豪雨 16 秒、停雨 180 秒；主要遊戲平衡尺度。
3. 長時間極端豪雨：豪雨 8 秒、停雨 6 秒、豪雨 20 秒、停雨 6 秒、豪雨 30 秒、停雨 360 秒。

全部使用相同固定地圖與乾燥起點。這三種是 debug scenario，未新增正式 UI 選項。

報告 B 為適量綠地對照：A 的 24 格改為 16 森林＋8 公園，仍有 66 住宅／工業。正式選單 B／E 沿用舊的全綠地配置（66 森林＋24 公園），因此不要把選單 B 的結果當成報告 B 數值。

C／D 沿用正式選單的相同 8 個靠河匯流格：第6、8欄，第2、5、7、9列，分別放下凹公園與調節池。固定道路與地圖不變。

## 試玩

選 A，豪雨前進 32 步（16 模擬秒），與 C／D 的相同步數比較。繼續前進數步觀察河川洪峰，再切晴天看退水。更換設施後按「重跑此配置」以乾燥起點比較；直接切天氣則保留土壤與蓄水。

低窪仍較早出問題，但排水超載會影響其他土地。有限滯洪保護不會涵蓋沒有經過設施的路徑；極端長雨後的差距可能縮小。完整數據與尚未達成的設計方向見 debug/PRESSURE-RESULTS.md。

水量、藍色高度與模擬秒均為教學相對尺度，不是毫米、真實深度或防災預報。本版維持固定主要路徑，不計算完整水面梯度、回水或多方向漫流。
